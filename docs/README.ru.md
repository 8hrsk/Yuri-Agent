<h1 align="center">Yuri Agent</h1>

<p align="center">
  Локальный desktop AI-компаньон с постоянной памятью, развивающейся личностью, явными разрешениями и взаимодействием нескольких агентов.
</p>

Yuri — персональное AI-пространство для одного владельца. Приложение объединяет desktop-чат, локальную долговременную память, настраиваемых агентов, фоновые задачи, голосовое взаимодействие, плагины и контролируемые диалоги между несколькими именованными агентами.

Проект в первую очередь ориентирован на macOS. Релизные сборки также создаются для Windows и, в экспериментальном режиме, Linux.

## Идея проекта

Большинство AI-чатов рассматривает каждый разговор как отдельную сессию либо хранит важное состояние в удалённом сервисе. Yuri использует другой подход:

- SQLite является главным локальным хранилищем диалогов, воспоминаний, состояния агентов, расписаний и журнала действий.
- У каждого именованного агента есть собственная модель, исходная идентичность, изменяемая личность, эмоциональное состояние, отношения и приватные воспоминания.
- Модель не может самостоятельно выдать себе разрешения или изменить заданные владельцем правила безопасности и идентичность.
- Изменение файлов и другие чувствительные действия проходят через policy-проверки и явные подтверждения.
- Диалоги могут создавать долговременные воспоминания; скрытие диалога не удаляет его историю или связанные воспоминания.
- Агенты могут вести ограниченные и аудируемые диалоги, не раскрывая друг другу приватный контекст.

Yuri написан на Go, Wails, React, TypeScript и SQLite.

## Основные возможности

- Потоковый чат через OpenAI-compatible providers и Codex App Server.
- Отдельные provider, model, fallback route и execution budget для каждого агента.
- Постоянная multi-agent память с приватными и явно опубликованными scope.
- Версионируемые personality, relationship, affect и owner-authored personalization данные.
- Голосовой ввод через совместимые speech-to-text providers и прерываемый системный text-to-speech.
- Файловые инструменты с подтверждением, ограниченный web-доступ и журнал с редактированными чувствительными данными.
- Расписания, фоновые запуски, проактивная активность и уведомления.
- Out-of-process плагины с проверкой manifest, capabilities, checksum и управлением жизненным циклом.
- Локальный поиск по архиву и зашифрованный экспорт/импорт агентов.

Полное описание находится в [техническом задании](PRODUCT_SPEC.md), [архитектуре](ARCHITECTURE.md) и [модели угроз](THREAT_MODEL.md).

## Установка из Releases

Готовые сборки, когда они доступны, публикуются на странице [GitHub Releases](https://github.com/8hrsk/Yuri-Agent/releases).

1. Скачайте пакет для своей операционной системы и соответствующий файл `.sha256`.
2. Проверьте архив перед запуском:

   ```bash
   shasum -a 256 -c yuri-<version>-macos-universal.zip.sha256
   ```

3. Распакуйте архив macOS/Linux или используйте Windows executable.
4. Откройте Yuri, создайте агента и подключите поддерживаемого model provider в onboarding.

Текущая OSS-сборка предназначена для macOS 11 и новее и содержит архитектуры Apple Silicon и Intel. Windows-пакеты публикуются для x64 и arm64. Если в описании релиза не указано обратное, community-артефакты не подписаны и не notarized. Перед запуском изучите release notes и проверьте checksum. Подробности находятся в [инструкции по выпуску macOS-сборок](MACOS_RELEASE.md).

> **Сборки для Linux экспериментальные и могут работать нестабильно.** Они создаются как нативные ELF-бинарники внутри Linux-контейнеров на self-hosted macOS build host. Используйте их в некритичной среде и сохраняйте резервную копию локального профиля Yuri.

## Версии и релизы

Yuri использует стабильное [семантическое версионирование](https://semver.org/lang/ru/) и теги вида `vMAJOR.MINOR.PATCH`. Каждый push в `main` запускает self-hosted release workflow. GitHub Release публикуется только после успешной сборки всех пакетов и checksum для macOS, Windows и Linux.

Начальная линия релизов задаётся файлом `VERSION`. После появления первого релиза conventional commit messages определяют автоматическое увеличение: `feat:` повышает minor, `BREAKING CHANGE:` или `type!:` — major, остальные изменения — patch. Увеличение `VERSION` выше последнего тега явно начинает новую линию релизов. Одна и та же версия встраивается в приложение и используется в именах артефактов.

## Сборка из исходного кода

### Требования

- macOS 11 или новее
- Xcode Command Line Tools
- Go 1.25
- Node.js 22 и npm
- GNU Make
- Docker Desktop с buildx (только для Linux release builds на macOS)

Клонируйте и проверьте проект:

```bash
git clone https://github.com/8hrsk/Yuri-Agent.git
cd Yuri-Agent
npm --prefix frontend ci
make check
```

Соберите desktop-приложение:

```bash
make macos-build
open cmd/yuri/build/bin/yuri.app
```

Команда `make macos-build` устанавливает закреплённую версию Wails CLI в локальную директорию `.tools` и создаёт universal macOS-приложение. Для создания и проверки распространяемого архива выполните:

```bash
make macos-smoke YURI_VERSION=0.7.0
```

Архив и checksum появятся в `dist/macos/`. Сам release workflow работает только на self-hosted macOS и Windows runner-ах репозитория; код из pull request на этих машинах не запускается.

Для разработки с hot reload:

```bash
make wails-install
cd cmd/yuri
../../.tools/wails dev
```

## Настройка provider

При первом запуске создайте агента и настройте один из поддерживаемых маршрутов через onboarding или Settings. Credentials обрабатываются backend и не должны попадать в репозиторий. На macOS секреты сохраняются через системный keyring boundary, а не в основной SQLite-базе.
