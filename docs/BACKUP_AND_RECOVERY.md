# Backup и восстановление

Yuri различает переносимый пользовательский backup и внутренний rollback-снимок миграции. Это разные артефакты с разными границами безопасности.

## Переносимый backup

Пользователь создаёт backup только явным действием в Settings. Приложение получает пароль на время одного Wails-вызова и не сохраняет его в SQLite, конфигурации, Keychain, логах или audit payload.

Формат `YURI-BKP1` содержит:

- согласованный SQLite snapshot, созданный через `VACUUM INTO`;
- очищенные несекретные настройки;
- опциональные файлы из blob directory;
- versioned manifest с размерами и SHA-256 каждого элемента.

Payload аутентифицируется и шифруется AES-256-GCM. Ключ длиной 256 бит выводится из пароля через scrypt с новой случайной salt для каждого экспорта. API keys, OAuth-токены, credential references и непроверенные пути исполняемых provider-файлов исключаются.

### Раскладка envelope

Файл начинается с cleartext-пролога: magic `YURIBKP1` (8 байт), длина заголовка (uint32 big-endian), затем JSON-заголовок ровно этой длины. Дальше идёт тело. Заголовок целиком входит в associated data AEAD, поэтому ни одно его поле нельзя отредактировать на месте.

Поле `version` в заголовке — дискриминатор формата тела, и restore диспетчеризуется по нему:

- `version: 1` — исторический формат. Тело целиком является одним ciphertext AES-256-GCM с nonce из заголовка. Заголовок несёт `plaintext_size`/`ciphertext_size` и не несёт `framing`/`chunk_size`. Такие архивы по-прежнему читаются и восстанавливаются, но больше не создаются: и запечатывание, и открытие требуют весь payload в памяти.
- `version: 2` — текущий формат, `framing: "stream-aes-256-gcm"`, `chunk_size` (по умолчанию 1 MiB, допустимо 4 KiB..8 MiB). Тело — последовательность кадров: каждый кадр это `chunk_size` байт plaintext (последний — меньше или пустой), запечатанных отдельно, то есть `chunk_size + 16` байт на диске. Поля `plaintext_size`/`ciphertext_size` равны нулю: размер payload неизвестен в момент, когда заголовок уже нужно аутентифицировать.

Nonce кадра (12 байт) — это `nonce[0:3] || uint64be(индекс кадра) || маркер`, где маркер равен 1 только у последнего кадра, а первые три байта берутся из случайного per-archive `nonce` заголовка. Associated data каждого кадра — `magic || байты заголовка`. Отсюда три свойства: кадр нельзя переставить (индекс входит в nonce), нельзя отбросить хвост потока (маркер последнего кадра), нельзя подставить кадр из другого архива тем же ключом (per-archive nonce prefix и associated data, покрывающая salt и nonce). Каждое из свойств покрыто отдельным adversarial-тестом в `internal/backup/stream_test.go`.

Импорт сначала проверяет envelope, KDF bounds, AEAD, пути, размеры, checksums, sanitized config и `PRAGMA integrity_check`. Расшифрованный payload и проверенный снимок SQLite стекают во временные файлы с правами `0600`, которые удаляются на любом пути выхода, включая отмену и ошибку; в памяти остаются только manifest и очищенный config. Все checksums проверяются до того, как restore тронет целевую директорию. Восстановление записывает файлы только в отдельную выбранную директорию с режимами `0700`/`0600`; существующие файлы и активная база Yuri никогда не перезаписываются. Активация восстановленной БД намеренно не автоматизирована в MVP.

Пароль восстановить невозможно. Потеря пароля означает потерю доступа к backup.

## Внутренний rollback-снимок миграции

Перед изменением существующей схемы SQLite создаётся локальный owner-only snapshot через SQLite online backup API, включая committed WAL state. Это не переносимый backup и не экспорт: он находится рядом с активной незашифрованной БД и имеет тот же at-rest trust boundary текущего macOS-профиля.

После успешной миграции snapshot и checksum metadata удаляются. Если миграция завершается ошибкой или процесс аварийно прекращается, snapshot остаётся для ручного восстановления и диагностируется через `VerifyBackup`. Поэтому пользовательский зашифрованный backup следует создавать до обновления приложения; rollback-снимок не заменяет его.

## Проверяемые гарантии

- Backup не перезаписывает уже существующий destination.
- Restore не перезаписывает существующие файлы и не следует через symlink ancestors.
- Повреждение ciphertext неотличимо от неверного пароля на границе AEAD.
- Размеры, число файлов, KDF work/memory и распакованный payload ограничены.
- Отмена не оставляет опубликованный неполный архив или тяжёлую scrypt goroutine.
- Audit содержит только имя файла и структурные metadata, но не пароль и не полный локальный путь.
